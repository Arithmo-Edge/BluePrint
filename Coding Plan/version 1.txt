২. ডাটাবেস স্কিমা (Firestore): শুরুতেই পূর্ণাঙ্গ প্রোফাইল তৈরি

BdMO Warm-Up-এ ইউজার যখন Gmail দিয়ে @handle বানাবে, তখনই তার ডাটাবেসে ভবিষ্যতের সব ফিল্ডের জায়গা (Default Value সহ) তৈরি হয়ে যাবে। ফলে পরে Wallet, 5 Arenas বা HQ Governance যোগ করলে পুরোনো ইউজারদের ডেটা নষ্ট হবে না:
json
{
  "handle": "@rayaan",
  "is_rated": true,
  "elo": {
    "mixed": 1200,        // BdMO Warm-Up এই অ্যারেনার ELO আপডেট করবে
    "number_theory": 1200, // ভবিষ্যতের জন্য রেডি থাকবে
    "algebra": 1200,
    "geometry": 1200,
    "combinatorics": 1200
  },
  "subscription": "Free",  // ভবিষ্যতে Plus/Pro/Singularity হবে
  "wallet_balance": 0.00,  // ভবিষ্যতের Arithmo Wallet
  "hq_elo": 0              // ভবিষ্যতের Governance র‍্যাংক
}
Use code with caution.
• Unrated ইউজারদের জন্য: যাদের @handle নেই, তারা engine.js-এর মাধ্যমে guest_mode: true হিসেবে খেলবে। তাদের ডেটা Firestore-এ না গিয়ে ব্রাউজারের localStorage-এ থাকবে, এবং লিডারবোর্ডে নামের পাশে [Unrated] দেখাবে।

৩. engine.js (Arithmo-Core-SDK): হুক-ভিত্তিক ডিজাইন

ক্লডকে দিয়ে engine.js বানানোর সময়ই তাতে ভবিষ্যতের ফিচারগুলোর জন্য Empty Hooks (খালি দরজা) রেখে দেবেন:
• সক্রিয় মডিউল (BdMO ম্যাচের জন্য): authModule() (Gmail SSO), readShieldCache() (স্ট্যাটিক JSON প্রশ্ন লোড), এবং submitSolution() (ছবি কম্প্রেশন + R2 আপলোড + মান/প্রমাণিত টেক্সট)।
• ভবিষ্যতের হুক (আপাতত নিষ্ক্রিয় থাকবে): aiMentorHook(), walletCheckoutHook(), module7ProctorHook()। পরের ভার্সনে ক্লড শুধু এই খালি ফাংশনগুলোর ভেতরে কোড বসাবে—আগের চালু থাকা কোডে হাত দেবে না।

৪. প্রশ্ন ও সাবমিশন পাইপলাইন (v1 থেকে v4 পর্যন্ত একই থাকবে)

• কাস্টম প্রশ্ন ফরম্যাট: আপনার ও জালিস হাবিবের তৈরি BdMO প্রশ্নগুলো contest-bdmo.json ফাইলে রাখবেন, যেখানে প্রতিটি প্রশ্নে arena_tag (mixed) এবং grading_type (VALUE বা PROOF) উল্লেখ থাকবে। ভবিষ্যতে আপনার Arithmo Database (Subsite #13) চালু হলে এই ফাইলটিই সরাসরি আর্কাইভ হিসেবে যুক্ত হয়ে যাবে!
• সাবমিশন ও গ্রেডিং: ইউজারের আপলোড করা খাতার ছবি + টেক্সট (মান বা প্রমাণিত) সরাসরি আপনার SymPy + Gemini Flash ব্যাকএন্ডে যাবে। আজ যা শুধু BdMO-এর খাতা দেখছে, আগামীকাল সেটিই আপনার ৪২-ইঞ্জিন এআই কোরের অংশ হয়ে যাবে।

৫. ELO ক্যালকুলেশন: ভবিষ্যতের ৬০-টিয়ার ম্যাট্রিক্সের সাথে সামঞ্জস্যপূর্ণ

• BdMO Warm-Up ম্যাচের স্কোরের ওপর ভিত্তি করে আপনার Python স্ক্রিপ্টটি ইউজারদের mixed (Mixed Mathematical Olympiad) অ্যারেনার ELO আপডেট করবে (শুরুতে সবার বেস ELO থাকবে ১২০০)।
• পরবর্তীতে যখন বাকি ৪টি অ্যারেনা এবং ৬০-টিয়ার ব্যাজ সিস্টেম চালু করবেন, তখন ইউজারদের এই BdMO ম্যাচের অর্জিত ELO-ই তাদের প্রোফাইলের স্থায়ী ভিত্তি হিসেবে থেকে যাবে।

ক্লডকে দেওয়ার জন্য গোল্ডেন রুল (Prompt Instruction)

ক্লডকে দিয়ে কাজ করানোর সময় প্রতিবার চ্যাটের শুরুতে এই একটি নির্দেশ দেবেন:
"আমরা একটি মডুলার ফেডারেটেড আর্কিটেকচারে কাজ করছি। বর্তমান টাস্কের জন্য শুধুমাত্র নির্ধারিত ফোল্ডার বা ফাংশনে কোড লিখবে। engine.js-এর বিদ্যমান অথেনটিকেশন, ডাটাবেস স্কিমা এবং আগে তৈরি হওয়া কোনো মডিউল পরিবর্তন বা ডিলিট করা যাবে না।"
এই পদ্ধতিতে এগোলে আপনার BdMO Warm-Up ম্যাচটি যেমন নির্বিঘ্নে ও দ্রুত লঞ্চ হবে, তেমনি প্রতিটি নতুন ভার্সন একের পর এক ইটের মতো বসে আপনার স্বপ্নের মেগা-ইকোসিস্টেমকে পূর্ণতা দেবে।





সর্বপ্রথম ভার্সন (Version 1.0 — যা আমরা শুধু BdMO Warm-Up ম্যাচ চালানোর জন্য ডিজাইন করেছি) হবে একদম ছিমছাম, দ্রুতগতির এবং "Zero-Throwaway" (কোনো কোড না মুছে বড় হওয়ার উপযোগী)।

১. Version 1.0-এর মূল কাঠামো (মাত্র ৪টি ফাইল/পেজ)

এই ভার্সনে ১৪টি আলাদা সাব-সাইট থাকবে না; একটি রিপোজিটরিতেই সব চলবে, কিন্তু ফোল্ডারগুলো এমনভাবে সাজানো থাকবে যাতে পরের ভার্সনগুলো সহজেই এর সাথে যুক্ত হতে পারে:
1. index.html (হোমপেজ ও ক্যাটাগরি হাব):
	• ইউজার এসেই Gmail SSO দিয়ে লগইন করে @handle (Rated) নিতে পারবে, অথবা লগইন ছাড়াই শুধু নাম দিয়ে Guest (Unrated) হিসেবে ঢুকতে পারবে।
	• নিচে ৪টি ক্যাটাগরির বড় বাটন থাকবে: Primary, Junior, Secondary, Higher Secondary।
2. contest/index.html (লাইভ কনটেস্ট অ্যারেনা):
	• আলাদা প্রাইভেট রিপোজিটরি (arithmo-bdmo-vault) থেকে সময়মতো (T-0) প্রশ্ন লোড হবে এবং KaTeX দিয়ে গণিতগুলো ঝকঝকে দেখাবে।
	• প্রতি প্রশ্নে সর্বোচ্চ ২ বার সাবমিশন: খাতার ছবি (ব্রাউজারে কম্প্রেস হয়ে ১৫০ KB WebP হয়ে Cloudflare R2-এ যাবে) + টেক্সট বক্সে চূড়ান্ত "মান" অথবা [ ✓ প্রমাণিত ] বাটন।
3. standings/index.html (লিডারবোর্ড):
	• লগইন ছাড়াই সবার জন্য উন্মুক্ত।
	• রেটেড (@handle) ও আনরেটেড ([Unrated]) ইউজারদের স্কোর এবং T+3h অডিটের পর আপডেট হওয়া mixed অ্যারেনার ELO দেখাবে।
4. sdk/engine.js (কেন্দ্রীয় মস্তিষ্ক):
	• লগইন, ফায়ারবেস কানেকশন (firestore.rules মেনে), ছবি কম্প্রেশন এবং ভবিষ্যতের ভার্সনগুলোর জন্য খালি হুক (aiMentorHook, walletCheckoutHook, module7ProctorHook) এখানে থাকবে।
